# Agentic stack benchmark

Verified against official repositories and documentation on 2026-09-02. This is an engineering license screen, not legal advice.

## Executable bake-off

The runnable package is isolated from the application at [`../benchmarks/agentic/`](../benchmarks/agentic/). `npm ci && npm run check` blocks `fetch`, HTTP(S) and TCP before dynamically importing either SDK, then uses only scripted local responses. The committed [machine result](../benchmarks/agentic/results/latest.json) is produced by the harness rather than transcribed by hand.

| Candidate            | Exact artifact                                                             | Measured result                                                                                                                               | Locked production surface | Verdict                                                                      |
| -------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- | ---------------------------------------------------------------------------- |
| Internal baseline    | Current `runAgentTeam` + `syntheticProfile`, AGPL-3.0-only                 | Same fixture, 16 tool calls, three reviews, one revision, JSON pause/resume, cancellation and invalid-output rejection                        | No added package          | Passes the in-process contract only.                                         |
| OpenAI Agents SDK TS | `@openai/agents@0.17.0`, MIT, integrity pinned by `package-lock.json`      | Same contract plus actual function tools, SDK handoff, approval interruption serialized through `RunState`, and `MaxTurnsExceededError` fault | 19 unique name/versions   | Passes this bake-off; remains only a candidate agent layer.                  |
| Mastra core          | `@mastra/core@1.63.2`, Apache-2.0, integrity pinned by `package-lock.json` | Same contract through Mastra Agents and tool workflow steps; peak three review calls; invalid Zod output fails closed; cancellation passes    | 135 unique name/versions  | Partial: durable resume and looping-agent limit enforcement remain unproved. |

All three produced one targeted revision with a configured cap of three, zero paid calls and zero unexpected network attempts. This is materially stronger than a hello-world, but it does not prove crash recovery, atomic budget settlement, tenant authorization or exactly-once effects.

The dependency counts are unique installed `name@version` nodes reachable from each direct runtime in `npm ls --omit=dev --all`; the combined isolated install is 220 MB. The readable harness and test are 607 TypeScript lines, including the network guard, three adapters and evidence capture. Its exact lockfile keeps SDK dependencies out of the production `package.json`. Mastra's published `test-utils/llm-mock` could not load in this minimal consumer because it imports undeclared `vitest`; the harness uses a structural AI SDK v4 local model through `generateLegacy` and records this as a DX limitation rather than adding Vitest. Mastra's package also contains `auth/ee` and `agent-builder/ee` declarations; the harness imports no `ee/` path. This is not yet an SBOM or bundle proof. `npm audit --omit=dev` reports two low findings in Mastra's `@ai-sdk/provider-utils` path at this snapshot and no moderate, high or critical finding.

Security is a symmetric gate, not a score adjustment: [Mastra `1.42.1`](https://github.com/advisories/GHSA-pp62-grrw-hvfp) had a package-compromise advisory with no patched version recorded; [Trigger.dev before `4.5.2`](https://github.com/triggerdotdev/trigger.dev/security/advisories/GHSA-9fq3-68cw-r7p2) had cross-tenant task replay; [`langgraph-checkpoint <3.0.0`](https://github.com/langchain-ai/langgraph/security/advisories/GHSA-wwqv-p2pp-99h5) had JSON deserialization RCE, and [`langgraph <=1.0.9`](https://github.com/advisories/ghsa-g48c-2wqr-h844) had unsafe msgpack deserialization. Any future evaluation must pin a patched version and preserve provenance evidence.

## Elimination criteria

Every component was checked for exact core/enterprise licensing, commercial managed-SaaS use, functional self-hosting, TypeScript fit, tenant isolation, durable resume, HITL, quotas, exportable tracing, security maturity, lock-in, operational cost and code it actually removes.

Permissive MIT/Apache-2.0 libraries can be included in this AGPL-3.0 product with their notices preserved. AGPL software can be used commercially; redistribution and modified network deployments carry corresponding-source duties. A separate HTTP service is not automatically a derivative work. Enterprise folders and hosted-service terms are separate gates.

## 5. Sandboxes, browsing and extraction

Agents receive no shell by default. Offer text paste is the guaranteed path; URL extraction begins with a bounded HTTP fetcher that revalidates DNS and every redirect, blocks loopback/private/link-local/metadata IPv4 and IPv6, restricts ports/MIME/bytes/time and runs behind an egress policy.

## Recommended stacks

### Current candidate stack

- Next.js + Zod + PostgreSQL/Supabase RLS.
- Explicit versioned state machine, artifact ledger and server-enforced budgets in Postgres.
- One direct structured-output provider SDK when generation becomes real; BYOK/local OpenAI-compatible endpoint for self-host.
- OpenTelemetry export boundary when model calls land.
- Plain SSRF-safe HTTP extraction first; no shell.
- Rootless Docker + Playwright only as a measured fallback.

ADR-002 remains proposed until the acceptance gates pass.

### Alternative at scale

- Temporal for durable multi-day workflows.
- OpenAI Agents SDK TS or Mastra core-only for bounded tool/handoff behavior if direct calls become inadequate.
- Langfuse core as an optional isolated observability profile.
- Envoy AI Gateway for Kubernetes-scale routing and quotas.
- Per-run sandbox workers; Hermes remains a dedicated single-tenant self-host option.

## Rejected or deferred

- Rejected now: CrewAI, LiteLLM, shared Hermes, E2B, Trigger.dev as the OSS durability contract.
- Deferred: Mastra, OpenAI Agents SDK, LangGraph, Temporal, Langfuse, Envoy AI Gateway, Firecrawl Cloud/self-host, Playwright worker.
- Explicitly excluded: Mastra `ee/`, LiteLLM `enterprise/`, Langfuse `ee/`, proprietary LangSmith/hosted gateway behavior as a required self-host dependency.
